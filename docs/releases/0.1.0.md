# SWF 0.1.0

SWF 0.1.0 is the first public preview of the Agentic Software Factory: a
local, service-backed system for turning OpenSpec changes into durable,
auditable agent workflows.

This is a pre-1.0 release. The command-line interface, API, stored-state
schema, configuration, and extension contracts may still change. Under the
project's versioning policy, a future `0.y.0` release may include breaking
changes; any such change will be called out in that release's notes.

## What's included

- A persistent, authenticated service that owns scheduling and active state.
- A `swf` CLI, a Vue dashboard, and a separately packaged Pi extension
  released in lockstep.
- The default Planning → Building → Reviewing → Verifying →
  Releasing workflow, with explicit checks, approval gates, phase contracts,
  evidence, checkpoints, and rollback.
- Isolated Git branches and worktrees, with pull-request or local-branch
  delivery selected by project policy.
- Pi, Codex CLI, Claude Code, and GitHub Copilot CLI adapters, including
  capability reporting and explicit model-tier routing.
- Durable cost, budget, retention, recovery, reconciliation, and run
  export/import records.
- User-scoped managed-service definitions for launchd on macOS and systemd on
  Linux. Installation, repair, and removal are previewed before they are
  applied.
- Reproducible package assembly and verification of the exact npm artifacts,
  including checksums, a CycloneDX SBOM, and release evidence.

## Install and get started

Install the product from npm:

```sh
npm install --global @chriskealley/swf@0.1.0
```

The Pi integration is published separately as
`@chriskealley/swf-pi@0.1.0`. Keep the product and extension on the same
version.

Check the host, initialize a trusted Git worktree, and start the local service:

```sh
swf doctor
swf init --cwd "$PWD" --trust
swf service start
swf new <change-name> --description "Describe the change"
```

`swf doctor` is non-mutating. SWF does not silently install tools, create
credentials, invent Git remotes, register background services, or overwrite
existing project configuration.

## Upgrade, downgrade, and stored state

Because 0.1.0 is the first release, there is no earlier public release to
upgrade from and no release migration is required.

For later upgrades, replacing the npm package will not restart the service or
migrate stored state. Run `swf upgrade` to preview the compatibility and
migration plan before applying any change. A service that cannot safely read a
newer state schema refuses to become the writer; restore a compatible backup
or install a compatible product version instead of forcing a downgrade.

Removing either the npm package or the managed-service definition preserves
service metadata, credentials, audit history, committed `.swf/` project
configuration, and `.swf-state/` operational history. Destructive cleanup is
a separate, scoped preview-and-confirm operation.

## Known limitations

- The product is pre-1.0 and does not yet carry a stable compatibility promise.
- Native Windows service management is preview-only.
- Homebrew, APT, RPM, container, and curl-based installers are not provided in
  this release.
- Harness features vary by adapter. Review capability diagnostics before
  relying on structured output, session resume, model selection, tool policy,
  or usage reporting.
- A managed-service definition can become stale when a Node version manager or
  package upgrade moves the executable. `swf service check` detects this and
  `swf service install --repair` previews the repair.

## Verify the release

The GitHub release contains the exact product and Pi-extension tarballs
published to npm, plus:

- `checksums.txt` with SHA-256 digests for both tarballs;
- `sbom.json`, a CycloneDX software bill of materials; and
- `release-evidence.json`, which records the source, toolchain, lockfile,
  artifact identities, smoke checks, and publication destinations.

The resolved dependency closure is recorded for diagnosis but is not part of
the verified artifact identity. A later npm install may resolve newer versions
that still satisfy the declared dependency ranges.
